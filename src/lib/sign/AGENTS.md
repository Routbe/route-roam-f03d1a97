# ROUT Sign rules (src/lib/sign)
- Phase 1 only: sanitized viewing, mandatory full scroll plus read timer, and a Sudo Mode (passkey) signature record bound to the signer's universal nullifier; nothing may call it PAdES, qualified or advanced until a QTSP adapter exists. Why: owner decision 2026-11-17 ("Nu zonder PAdES").
- PDFs exist outside the browser only as RSG1 envelopes (`sign-envelope.ts`, AES-256-GCM, 64 KiB buckets, role-bound AAD); the document key lives only in the link fragment and is sealed, opened and attested only through the crypto worker ops `sign.seal` / `sign.open` / `sign.attest`. Why: the server and Neon never hold plaintext or a key.
- Every document is shown and signed only after `pdf-sanitizer.ts`; it refuses what it cannot reason about instead of passing it through, and the signed copy is the sanitized PDF, so what is shown is what is signed. Why: no embedded scripts, launch actions or hidden text can reach a signer.
- A signature is recorded only by `rout_sign_request_mark_signed` with the stored envelope's SHA-256 (db/0290) and a binding computed server-side; the nullifier never leaves `sign.server.ts`. Why: a signature can never be attached to a different document or person.
